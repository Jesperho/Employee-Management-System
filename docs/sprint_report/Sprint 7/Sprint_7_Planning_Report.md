## Sprint Goal

The goal of Sprint 7 is to ensure that the product is functional, usable, and aligned with the initial requirements defined by the Product Owner. This sprint focuses on testing both functional and non-functional aspects of the system.

---

## Selected Product Backlog Items

- Perform functional testing
- Perform non-functional testing
- Write the Sprint 7 Deliverable Report
- Prepare Sprint 7 documentation

---

## Planned Tasks / Breakdown

### 1. Functional Testing Tasks
- Create a test plan that includes objectives, resources, test environment, and test tasks (both functional and non-functional).
- Conduct unit testing to verify the functionality of implemented features, especially after code cleanup.
- Create and maintain a bug-tracking table to record and address issues identified during testing.
- Review and refine user stories in Trello based on the latest software functionality.
- Use Jenkins to generate static code analysis reports, along with successful project builds and Docker deployment.
- Ensure that the static code analysis report (SonarQube) achieves grades of A, or at minimum B.

---

### 2. Non-Functional Tasks
- Conduct heuristic evaluation of the system.
- Perform User Acceptance Testing (UAT).
- Document specification and architectural changes based on test results.
- Record and reflect all changes made during the sprint in Trello and GitHub.

---

### 3. Sprint 7 Deliverable Report
- Provide a summary of the work completed, including tasks undertaken and features implemented.
- Describe challenges encountered during feature implementation and how they were resolved.
- Present results of unit and integration testing, including bugs identified and fixed.
- Include screenshots of the SonarQube reports generated via Jenkins.
- Provide the heuristic evaluation report.
- Present User Acceptance Testing (UAT) results.
- Summarize security testing findings and mitigation actions taken.
